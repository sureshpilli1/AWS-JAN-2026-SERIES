1. Introduction to EventBridge
EventBridge is a serverless event bus service used to build event-driven architecture.
Instead of writing scripts to monitor AWS services, EventBridge automatically captures events from AWS services and routes them to targets like:
Lambda
SNS
SQS
Step Functions
EC2
ECS

Basic Flow:
AWS Service → EventBridge → Rule → Target

In this lab:
EC2 state change → SNS email
IAM user creation/deletion → SNS email

2. Create CloudTrail (Mandatory for IAM Events)
Important:
EC2 state-change events are native events.
IAM API events (CreateUser/DeleteUser) are captured through CloudTrail.
Step-by-Step:
1. Go to CloudTrail
2. Click Create trail
3. Trail name: kk-eventbridge-trail
4. Storage location:
   * Create new S3 bucket
   * Example: kk-eventbridge-cloudtrail-logs
5. Enable:
   * Management events → Read/Write
   * Multi-region trail → Recommended
6. Click Create trail
Now IAM API calls will be recorded.

3. Create SNS Topic and Subscription
Step 1: Create SNS Topic
1. Go to SNS
2. Click Create topic
3. Type: Standard
4. Name: kk-eventbridge-topic
5. Create topic
Step 2: Create Subscription
1. Open the topic
2. Click Create subscription
3. Protocol: Email
4. Endpoint: your email address
5. Create subscription
6. Confirm email from inbox
Now SNS is ready.

4. EventBridge Rule for EC2 Stopping and Stopped State
Objective:
Send email when EC2 instance goes into stopping or stopped state.
Step 1: Create Rule
1. Go to EventBridge
2. Click Rules
3. Create rule
Name:
kk-ec2-state-rule
Rule type:
Event pattern
Event source:
AWS services
Service:
EC2
Event type:
EC2 Instance State-change Notification

Step 2: Use Custom Event Pattern (Advanced)
Instead of selecting manually, use this JSON:

```json
{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": {
    "state": ["stopping", "stopped"]
  }
}
```

This filters only stopping and stopped.

Step 3: Select Target
Target type:
SNS topic
Select:
kk-eventbridge-topic

Step 4: Configure Input Transformer
Click Configure input transformer
Input Paths:

```json
{
  "instance": "$.detail.instance-id",
  "state": "$.detail.state",
  "region": "$.region",
  "time": "$.time"
}
```

Input Template:

```json
{
  "Message": "EC2 Instance <instance> is now <state> in region <region> at <time>"
}
```

Save rule.

5. EventBridge Rule for IAM User Creation and Deletion
Important:
IAM events are captured through CloudTrail.
So Event source = CloudTrail API calls.
Step 1: Create New Rule
Name:
kk-iam-user-events-rule
Rule type:
Event pattern
Event source:
AWS services
Service:
CloudTrail
Event type:
AWS API Call via CloudTrail
Step 2: Use Custom Event Pattern

```json
{
  "source": ["aws.iam"],
  "detail-type": ["AWS API Call via CloudTrail"],
  "detail": {
    "eventSource": ["iam.amazonaws.com"],
    "eventName": ["CreateUser", "DeleteUser"]
  }
}
```

This filters:
IAM user creation
IAM user deletion

---

Step 3: Select Target
Target:
SNS topic

Select:
kk-eventbridge-topic

Step 4: Configure Input Transformer
Input Paths:

```json
{
  "username": "$.detail.requestParameters.userName",
  "event": "$.detail.eventName",
  "time": "$.detail.eventTime",
  "caller": "$.detail.userIdentity.arn"
}
```

Input Template:

```json
{
  "Message": "IAM Event: <event> performed on user <username> at <time> by <caller>"
}
```

Save rule.

what is meant by serverless service:
One-Line Definition
A serverless service is a cloud service where the cloud provider manages all underlying servers and infrastructure, allowing you to focus only on using the service and its features.
So when AWS says:
"Amazon EventBridge is a serverless event bus service"
it means:
EventBridge provides an event bus for routing events, while AWS handles all the servers, scaling, maintenance, and availability behind the scenes.

what is input transformer:
Input Transformer
Without a transformer, SNS receives the whole JSON event.
Something ugly like:
{
  "version":"0",
  "id":"abcd",
  ...
}
Instead, you extract only useful fields.
Input Paths:
{
  "instance": "$.detail.instance-id",
  "state": "$.detail.state",
  "region": "$.region",
  "time": "$.time"
}
This means:
instance -> instance-id
state    -> state
region   -> AWS region
time     -> event timestamp
Then EventBridge builds a custom message:
{
  "Message": "EC2 Instance <instance> is now <state> in region <region> at <time>"
}
Example output:
EC2 Instance i-0abc123 is now stopped in region us-east-1 at 2026-08-10T10:30:00Z
SNS emails this message.











explanation for native events and API events:
--------------------------------------------



API stands for Application Programming Interface.
In simple words, an API is a communication interface that allows two software applications or systems to communicate with each other.
Example in AWS
Suppose you want to stop an EC2 instance.
You send a request using the StopInstances API.
- Application: AWS Management Console or AWS CLI.
- API: StopInstances.
- Service: Amazon EC2.
- Result: EC2 processes the request to stop the instance.

An API call is a request sent by one software application to another software application to perform a particular operation.
In AWS, when you want to start, stop, reboot or terminate an EC2 instance, your request is sent to the Amazon EC2 service through an API.
Let's understand this step by step.

1. What are StartInstances and StopInstances?
These are API operations provided by the Amazon EC2 service.
API operation	What it does
StartInstances	           Starts a stopped EC2 instance
StopInstances	             Stops a running EC2 instance
RebootInstances	           Restarts an EC2 instance
TerminateInstances	       Permanently terminates an EC2 instance
For example, suppose you have an EC2 instance named WebServer.
When you click the Stop button in the AWS Console, AWS sends a StopInstances API request to the EC2 service.
You don't need to write the API call yourself. AWS Console does it behind the scenes.

2. How can you make an API call?
There are three common ways.
Method 1: AWS Management Console
You select an EC2 instance and click:
Instance state → Stop instance.
AWS Console sends the API request internally.

Method 2: AWS CLI
You can send the same request using a command:
Stop an instance:
aws ec2 stop-instances \
  --instance-ids i-1234567890abcdef0

Start an instance:
aws ec2 start-instances \
  --instance-ids i-1234567890abcdef0
Here:
- aws = AWS CLI program.
- ec2 = AWS service.
- stop-instances = API operation.
- --instance-ids = Specifies which EC2 instance you want to stop.

Method 3: AWS SDK
You can also write a program in Python, Java or another supported language to make API requests.
For example, Python using Boto3:
import boto3ec2 = boto3.client('ec2')ec2.stop_instances(    InstanceIds=['i-1234567890abcdef0'])
Here, the Python program sends the StopInstances API request to AWS.


How does CloudTrail capture API calls?
For example, CloudTrail can record details like:
Field	               Example
Event source	       ec2.amazonaws.com
Event name	         StopInstances
Username	           admin
Event time	         Date and time of request
Resource	           EC2 instance ID

4. Important difference to remember
Consider this situation:
You click Stop on an EC2 instance.
Two things can happen:
1. API activity: Someone requested EC2 to stop the instance (StopInstances).
2. State change: The EC2 instance actually transitions from running to stopping and then stopped.
These are different events.
- CloudTrail helps answer: Who requested the stop operation?
- EC2 state-change event helps answer: What happened to the instance's state?
This distinction is important when learning AWS EventBridge and CloudTrail.



EC2 state-change events and EC2 API activity are two different types of events.
Let's compare them.
1. EC2 state-change events
These events are generated directly by the EC2 service and delivered to Amazon EventBridge.
For example:
- EC2 instance changes from pending to running.
- EC2 instance changes from running to stopping.
- EC2 instance changes from stopping to stopped.
These events are not dependent on CloudTrail.

Example EventBridge event:
{
  "source": "aws.ec2",
  "detail-type": "EC2 Instance State-change Notification",
  "detail": {
    "state": "stopped",
    "instance-id": "i-1234567890abcdef0"
  }
}


2. EC2 API events captured by CloudTrail
When someone performs an API operation, CloudTrail records that activity as a management event.
Examples:
API operation	Meaning
StartInstances	            Request to start an EC2 instance
StopInstances	              Request to stop an EC2 instance
TerminateInstances	        Request to terminate an EC2 instance
RebootInstances	            Request to reboot an EC2 instance

CloudTrail can tell you:
- Who made the API request.
- When the request was made.
- Which API operation was performed.
- Which resources were involved.
These CloudTrail events can also be delivered to EventBridge.

3. Understand the difference
EC2 native service event
EC2 state changes
EC2 → EventBridge
Tells you what happened to the instance state.
CloudTrail management event
EC2 API activity
User → EC2 API → CloudTrail → EventBridge
Tells you who requested an operation and what API was called.

4. One practical example
Suppose you click Stop on an EC2 instance.
Question	                                         Event source
Who requested the instance to stop?	               CloudTrail
Which API was called?	                             CloudTrail (StopInstances)
Did the instance change to stopped?	               EC2 state-change event
Can EventBridge trigger an email notification?	   Yes, using either event type

Final correction to your statement:

Your understanding should be:
- EC2 state-change events are native events sent directly to EventBridge; they do not require CloudTrail.
- EC2 API calls such as StartInstances and StopInstances are recorded by CloudTrail as management events.
- Both types of events can be used as EventBridge rule inputs.
One more important point: CloudTrail captures many AWS service API activities, not just IAM API events. StartInstances and StopInstances are EC2 API operations, not IAM API operations.
